ADVANCED RAG — SAMPLE KNOWLEDGE BASE

SECTION 1: WHAT IS RAG?
Retrieval-Augmented Generation (RAG) is an application pattern in which a system retrieves relevant passages from an external knowledge source and supplies those passages to a language model as context. The model then generates an answer grounded in the retrieved material. RAG is useful when an application must answer questions about private, specialized, or frequently changing documents. A RAG system typically includes document ingestion, text extraction, chunking, indexing, retrieval, context selection, and answer generation.

SECTION 2: DOCUMENT CHUNKING
A document is often divided into smaller text segments called chunks before indexing. Chunk size affects retrieval precision and context completeness. Very small chunks may omit definitions or surrounding explanations needed to understand a fact. Very large chunks may contain unrelated paragraphs, increase embedding and retrieval costs, and consume more of the language model's context window. Chunk overlap repeats a small amount of text between neighboring chunks. Overlap can preserve meaning when a sentence or concept crosses a chunk boundary. Chunking should be tested against the structure and length of the source documents rather than chosen by habit. Headings, paragraphs, and semantic boundaries can be useful split points.

SECTION 3: SEMANTIC SEARCH AND EMBEDDINGS
An embedding model converts text into a numerical vector. Texts with related meanings can have vectors that are close in the embedding space, even when they do not share the same exact words. Semantic search embeds a user query and compares it with document-chunk embeddings, often using cosine similarity. Semantic search is useful for natural-language questions, paraphrases, and concept-based retrieval. It may be weaker when the question depends on an exact identifier, a rare product code, a person's name, or a precise acronym that the embedding model does not represent distinctly.

SECTION 4: KEYWORD SEARCH AND BM25
Keyword search ranks documents using the words that appear in the query and the documents. BM25 is a probabilistic keyword-ranking function that considers term frequency, inverse document frequency, and document length. It is often effective for exact names, technical identifiers, error codes, acronyms, and rare terms. Keyword retrieval can miss a passage when the user expresses the same concept with different words. It can also overvalue repeated terms if the query is vague. BM25 and semantic search therefore have complementary strengths.

SECTION 5: HYBRID SEARCH AND RECIPROCAL RANK FUSION
Hybrid search combines two or more retrieval methods, commonly semantic vector search and keyword search. The goal is to improve recall by retrieving passages that either method may find useful. The raw scores from different retrievers are not necessarily comparable: cosine similarity and BM25 scores have different ranges and meanings. Reciprocal Rank Fusion (RRF) combines ranked lists using each document's rank rather than adding raw scores. A common formula is RRF(d) = sum over retrievers of 1 / (k + rank(d)). The constant k is often set to 60. A document ranked highly by multiple retrievers receives a stronger combined score. RRF is a simple rank-fusion method and does not require score calibration.

SECTION 6: RERANKING
A reranker receives a query and a smaller candidate set returned by the first-stage retriever. It estimates how relevant each candidate passage is to the query and reorders the candidates. A cross-encoder processes the query and passage together, allowing more direct interaction between their words. This can produce a more precise relevance order than independently embedding the query and passage. Cross-encoders are usually slower than bi-encoder retrieval, so they are commonly applied only to a limited candidate set. The top reranked chunks are selected as context for the language model. Reranking improves ordering, but it cannot recover a relevant passage that the initial retrieval stage failed to include.

SECTION 7: GROUNDED ANSWERS AND ABSTENTION
The answer-generation step should receive only the most relevant selected chunks, along with instructions to answer from those sources. A grounded answer should distinguish supported facts from missing information and identify the source passages used. If the retrieved context does not contain enough evidence, the assistant should abstain rather than invent an answer. Prompt instructions alone do not guarantee abstention; evaluation should include many questions whose answers are deliberately absent from the knowledge base. Systems can also use retrieval thresholds, evidence checks, and human review to improve reliability.

SECTION 8: BASIC RAG EVALUATION
A basic evaluation set should include answerable questions, unanswerable questions, exact-term questions, and paraphrased questions. Retrieval evaluation asks whether the relevant passage appears in the candidate set. Reranking evaluation asks whether relevant passages move toward the top. Answer evaluation checks factual correctness, grounding, and source citations. Abstention evaluation checks whether the system declines to answer when the document collection lacks evidence. A useful manual test records the question, expected source chunk, retrieved candidates, reranked context, generated answer, and whether the answer is supported.

The sample knowledge base does not specify the price of a laptop, a user's home address, or tomorrow's weather forecast. It also does not provide a company phone number or a bank account balance.
